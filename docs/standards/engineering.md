# Engineering Standard

## Scope

This standard applies to Java Flink jobs, Python collectors, container images, Kubernetes manifests, scripts, and shared libraries. It supplements [`Instructions.md`](../../Instructions.md) and the standards [index](README.md).

## Code and configuration

- Code MUST handle expected failures explicitly. It MUST preserve actionable context and MUST NOT swallow exceptions, return fabricated success, or log secret-bearing values.
- Retries MUST be bounded, use timeouts and backoff, and be safe under duplication. Do not retry non-idempotent external side effects without an idempotency mechanism.
- Configuration MUST be explicit, validated at startup, and injectable per environment. Defaults MUST be safe and documented; secrets MUST come from the approved secret path, never source code or plaintext configuration.
- Public functions, configuration keys, resource names, and metric names MUST have stable, unambiguous names. Breaking changes require an approved design and migration plan.

## Java and Python quality

- Java changes MUST compile at the affected Maven module boundary and test deterministic business logic without requiring live infrastructure where possible.
- Python changes MUST use pinned dependencies, explicit timeouts for network calls, and tests for configuration parsing, health behavior, retry boundaries, and failure handling when applicable.
- Type checks, linting, and test failures are release blockers unless an approved time-bound exception exists.

## Containers and Kubernetes

- Images MUST be reproducible, use a minimal trusted base, run as a non-root user, and use immutable versioned references in deployment manifests.
- Workloads MUST declare resource requests and limits appropriate to their observed load and failure behavior. Resource settings are hypotheses until validated by runtime evidence.
- Readiness probes MUST represent the ability to serve or consume safely; liveness probes MUST detect a recoverable stuck state. Neither may hide dependency failure or cause destructive restart loops.
- Manifests MUST use least-privilege service accounts, explicit namespaces, and controlled ConfigMap/Secret injection. Do not rely on an implicit current namespace or developer-machine state.

## Repository hygiene

- Do not commit IDE metadata, dependency caches, generated bytecode, runtime dumps, local screenshots, build outputs, or copied libraries unless intentional versioning is documented and reviewed.
- Keep changes focused. Refactors that are not needed for the requested behavior belong in a separately reviewed change.
